# Public FAQ draft

## Does Luma work offline?

The core reader/editor, Piper speech and OCR work locally after installation of the required runtime and models. Downloads and any external pages require a connection. The current app does not offer a cloud voice service.

## What can I open?

PDF, DOCX, TXT, Markdown and HTML. PDF reading keeps the original page visible. Markdown is the default format for new notes; existing HTML notes can retain rich formatting.

## Can it read scanned books and figures?

OCR can recover legible text, captions and labels. It can make mistakes, and reading order in tables or columns may be imperfect. It does not explain the meaning of diagrams or replace checking the original page.

## Are the voices created by Luma?

Not yet. The current build uses Piper and a reviewed Cori high model by Bryce Beattie, derived from LibriVox recordings. An original Luma voice is a future consent-and-recording project.

## Will the voices work in Word, NaturalReader or other readers?

System-wide voice integration is separate work and is not included as a verified feature of this candidate. Do not assume a voice bundled with Luma automatically appears in other applications.

## Is it open source and free?

The community source is licensed under AGPL-3.0-or-later. Public release preparation is ongoing. Other components and model files have separate licences. Financial support is optional; a future premium offer has not been finalised.

## Is it ready for every Windows computer?

It is a development preview tested on a limited configuration. Review the known issues and test notes. Broader clean-machine, scaling, monitor and upgrade checks remain open.

## What does support pay for?

Optional support helps the student developer sustain development time and contribute toward university fees. No fixed allocation, charitable status, release deadline or premium entitlement is promised.

## Does it upload my documents?

Core reading, OCR and synthesis operate locally. The current app has no document-upload or cloud voice workflow. If future online features are introduced, their data handling must be explained before use. Public bug reports are separate; avoid including private documents or unredacted logs.
